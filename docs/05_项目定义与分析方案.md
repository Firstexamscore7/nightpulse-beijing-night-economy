# 试点策划决策看板：项目定义与分析方案 v0.1

## 一句话定义

把既有的“节气文化与北京夜间经济”调研，改造成一套供夜间文化活动或商圈运营团队使用的**试点策划决策看板**：用问卷证据帮助团队选择优先活动类型、识别主要体验堵点，并形成可验证的小规模试点假设。

## 使用者与决策

| 项目 | 定义 |
| --- | --- |
| 主要使用者 | 商圈、街区或夜间文化活动的运营与策划团队 |
| 核心决策 | 先试哪类节气活动；优先改善哪些体验堵点；把试点面向哪类行为人群 |
| 使用阶段 | 活动立项与小规模试点前，不替代真实经营数据和现场调研 |
| 当前证据 | 982份问卷中的自报行为、偏好、态度和反事实意向 |
| 不支持的结论 | 真实客流增量、营收提升、因果效果、政策实施效果或个人级精准预测 |

## 分析问题

1. 受访者更偏好哪些节气活动形式？
2. 当前夜间消费体验中，哪些问题最突出？
3. 哪些可观察特征与“更高的自报节气活动参与增加意向”相关？
4. 全量样本、旧版932样本与去重敏感性样本的结论是否基本一致？

## 结果变量

主分析把 `expected_visits_after_seasonal_events` 大于全量样本中位数7次定义为：

> `higher_stated_increase = 1`

该标签只表示“样本内较高的自报增加意向”。它不是实际到访、转化或增量客流。采用“大于中位数”而不是“大于等于中位数”，是为了得到较平衡的二分类结果，并保留清晰、可复现的阈值。

## 默认模型特征

模型只使用策划团队在试点前可以理解和讨论、且现有编码相对明确的字段：

- 当前夜间消费频率与消费场景选择；
- 周边可达性、可达性堵点与体验性堵点；
- 情感价值、社会价值、功能质量和“物有所值”；
- 四类活动偏好；
- 社区集市、延长地铁和社交媒体推广需求。

以下字段不进入默认模型：

- `source_id` 及所有审计字段：不是业务特征；
- 性别、年龄等人口属性：第一版避免把敏感属性用于决策；只在后续必要时做公平性检查；
- 常住区域、收入、职业、学历：缺少完整编码表，收入还有行级映射风险；
- `need_seasonal_events`：与结果变量语义过近，容易形成信息泄漏；
- 交通改善后预计增加次数、溢价比例、愿意支付溢价：同属意向结果或存在旧清洗争议；
- 功能价格综合分：其中包含“愿意支付溢价”，因此改用单项“物有所值”。

## 方法

### 描述性决策层

- 活动偏好选择率；
- 十项体验与交通堵点的均值排序；
- 按当前消费频率分组的需求和偏好；
- 高、低自报增加意向组的差异，仅作描述，不作因果解释。

### 可解释建模层

- 固定随机种子20261010；
- 五折分层交叉验证；
- L2正则逻辑回归，用标准化系数解释方向和相对强弱；
- 分别设置“仅当前消费频率”和“去掉当前消费频率”的对照模型，识别高表现是否主要由单一行为变量驱动；
- 深度不超过3、叶节点不少于40条记录的浅层决策树，用于展示简单规则；
- 与“总是预测多数类”的基线比较；
- 指标包括 AUC、平衡准确率、F1、准确率和 Brier 分数；
- 不报告显著性或因果效应，不把模型分数包装为真实消费概率。

### 敏感性分析

同一套流程分别运行在：

1. 全量原始视图（982条）；
2. 旧版纳入视图（932条）；
3. 旧版纳入且完全重复组只保留首条的视图（893条）。

## 交付物边界

- Dashboard 只展示聚合结果，不展示逐条问卷数据；
- 私有分析CSV暂不公开上传，待确认团队和数据授权；
- 模型是作品集中的“分析原型”，不是已上线算法；
- 后续真实试点应补充到访、核销、客单价或停留时长等行为指标，并预先设定对照或前后比较方案。

## 试点建议的验证框架

当前问卷最多支持提出假设。真正验证时，可以按以下结构执行：

| 层级 | 示例指标 |
| --- | --- |
| 活动投入 | 活动场次、内容类型、推广渠道、运营成本 |
| 过程指标 | 曝光、预约、到场、停留时长、互动完成率 |
| 结果指标 | 核销量、复访、客单价或满意度变化 |
| 风险检查 | 投诉、安全事件、拥堵、噪声与无障碍问题 |

最终对外表述应区分“问卷意向”“模型关联”“试点实测”三个证据等级。
